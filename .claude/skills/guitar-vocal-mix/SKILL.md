# Сведение голос + гитара

Проекты в `~/projects/music/<Исполнитель> - <Название>/`. Контекст железа и текущее состояние - в `CLAUDE.md` этой папки.

## Рабочий цикл

Измерить -> решить -> применить -> проверить. Ни один шаг не пропускать: цифры регулярно опровергают интуитивные настройки.

### 1. Измерить

REAPER пишет вход **до обработки**, поэтому сырые дубли годятся для диагностики источника, но не для оценки микса. Обрезка в REAPER неразрушающая - в файле лежит полный дубль, а использованный кусок задан в айтеме:

```
POSITION 0        # где айтем на таймлайне
SOFFS 20          # смещение от начала исходника, сек
LENGTH 239.5      # длительность используемого куска, сек
```

Вырезать рабочий участок перед замером - иначе тишина в хвостах перекосит LUFS и шумовой пол:

```bash
ffmpeg -v error -ss <SOFFS> -t <LENGTH> -i Media/<файл>.wav -c:a pcm_s24le -y /tmp/<трек>.wav
```

Это работает, когда на треке **один** айтем. Если дубль нарезан на куски (несколько блоков `SOFFS`/`LENGTH` подряд), склеивать их в порядке `POSITION` через `concat`, либо мерять уже по рендеру - иначе замер уйдёт по кускам, которые в песню не вошли.

Дальше `mcp__phantom__full_diagnostic` по каждому треку и `mcp__phantom__analyze_masking` между гитарой и голосом. При двух инструментах маскирование - главный вопрос сведения.

### 2. Решить

Сначала гейн-стейджинг, только потом тембр. Порядок важен: компрессор с порогом выше уровня сигнала не работает вообще, и никакая эквализация этого не заметит.

Проверять всегда:

- **Порог компрессора против RMS трека.** Если RMS ниже порога - компрессор мёртвый груз. Поднимать вход `utility/volume`, а не опускать порог вслепую.
- **Пик против 0 dBFS.** Если дубль уже в потолке, любой makeup гонит в клип. Ставить отрицательный трим первым в цепочку.
- **Баланс.** Голос ведёт, гитара обычно на 4-6 LU ниже. Считать по integrated LUFS, не на глаз.

Фейдер трека в REAPER стоит **после** цепочки, поэтому для запаса перед обработкой он бесполезен - нужен трим-плагин первым звеном.

### 3. Применить

Два пути:

- **REAPER открыт** - через `mcp__reaper__*`. Мост живёт только пока REAPER запущен.
- **REAPER закрыт** - править `.RPP` напрямую. Быстрее и надёжнее для пакетных правок.

Правила редактирования `.RPP` - ниже, они неочевидны и уже стоили одной поломки файла.

### 4. Проверить

Отрендерить и померять результат. Симуляция суммы через ffmpeg даёт оценку в пределах пары дБ и годится, чтобы подобрать порог лимитера заранее:

```bash
ffmpeg -v error -i guitar.wav -i mic.wav -filter_complex \
  "[0:a]volume=<G>dB[g];[1:a]volume=<V>dB,pan=stereo|c0=c0|c1=c0[m];\
   [g][m]amix=inputs=2:normalize=0:duration=longest[out]" \
  -map "[out]" -c:a pcm_s24le -y /tmp/mix_sim.wav
```

## Правки .RPP: чему учит опыт

**Файл в CRLF.** REAPER пишет `.RPP` с `\r\n`. Python в текстовом режиме молча съедает `\r` и сохраняет LF. Читать и писать **только в бинарном режиме**, либо восстанавливать CRLF после:

```python
raw = open(path, "rb").read()
# ...правки над raw.decode("utf-8")...
open(path, "wb").write(new.encode("utf-8").replace(b"\n", b"\r\n"))
```

Проверка целостности после правки: посчитать sha256 блока, который не трогал (например ReaVerb), и сверить с бэкапом.

**Параметры JSFX - ровно 64 токена.** Значения слайдеров по порядку, остаток добивается `-`. Это и есть причина брать JSFX вместо VST: у VST состояние лежит в base64-чанке, который вслепую не собрать.

**Структура звена в FXCHAIN:**

```
      BYPASS <0|1> 0 0
      <JS <категория>/<плагин> ""
        <64 токена>
      >
      FLOATPOS 0 0 0 0
      FXID {UUID-В-ВЕРХНЕМ-РЕГИСТРЕ}
      WAK 0 0
```

`BYPASS 1` = звено выключено. У VST после `>` идёт ещё `PRESETNAME "..."`.

**`FX 0` у трека - вся цепочка выключена**, независимо от `BYPASS` отдельных звеньев. Пользователь намеренно ставит `FX 0` на время записи, чтобы писать насухо. Не «чинить» это молча.

**Валидация после правки:**

```python
# баланс блоков должен сойтись в 0; каждая строка параметров JS - 64 токена
```

## Плагины: порядок слайдеров

Проверено по исходникам в `/Applications/REAPER.app/Contents/InstallFiles/Effects`.

| Плагин | Слайдеры |
|---|---|
| `utility/volume` | Adjustment dB, **Max Volume dB** |
| `sstillwell/hpflpf` | HPF, LPF, Gain |
| `sstillwell/rbj4eq` | f1, gain1, f2, gain2, f3, gain3, f4, gain4 |
| `sstillwell/1175` | Threshold, Ratio, Gain, Attack us, Release ms, Mix % |
| `sstillwell/expander` | Threshold, Ratio, Gain, Detector, Detection, Attack ms, Release ms |
| `Liteon/presenceeq` | Processing, Freq, Cut/Boost, Bandwidth, Output |
| `Liteon/deesser` | Processing, Target, Monitor, Freq, BW, Threshold, Ratio, TimeConst, Gain |
| `loser/MGA_JSLimiterST` | Threshold, Release ms, Link %, Ceiling |

Ловушки:

- **`utility/volume`, слайдер 2 «Max Volume»** - это жёсткий клип (`min(max(spl*adj1, -adj2), adj2)`), а не индикатор. При значении 0 режет по 0 dBFS. Ставить 40, иначе трим превращается в клиппер.
- **`MGA_JSLimiterST` сам компенсирует громкость**: `volume = ceiling/thresh`, то есть усиление = `ceiling - threshold`. Порог задаётся от измеренного уровня микса, а не «на глаз».
- **`1175`, слайдер Ratio - индекс, а не число.** `{0..4}` - устаревшие Blown Capacitor, `5`=4:1, `6`=8:1, `7`=12:1, `8`=20:1, `9`=All.
- **`rbj4eq` - фиксированные частоты**, слайдер частоты это индекс 1-5:

  | Полоса | Частоты |
  |---|---|
  | 1 | 40, 80, 160, 315, 500 |
  | 2 | 125, 250, 500, 1k, 2k |
  | 3 | 315, 630, 1.2k, 2.5k, 5k |
  | 4 | 1.6k, 3.2k, 6.4k, 9k, 12k |

- **Штатного JSFX-ревера нет.** В `delay/` и `misc/` реверов не лежит. Остаётся ReaVerb с base64-чанком - его включать/выключать можно, а баланс сухого и мокрого правит только пользователь.

## Что даёт эта связка

Замеры первой сессии, как ориентир для типовых ошибок этого тракта:

| | вокал | гитара |
|---|---|---|
| Integrated | -18.4 LUFS | -30.8 LUFS |
| Пик | 0.0 dBFS | -10.2 dBFS |
| SNR | 24.8 дБ | 7.4 дБ |

Характерные перекосы:

- **Микрофон легко перекрутить** - ATR2100x упирается в 0 dBFS и даёт клиппинг. Просить пики в районе -12...-6 dBFS.
- **NUX отдаёт очень тихо** - типично на 12 LU ниже голоса, отсюда SNR около 7 дБ. Это лечится только перезаписью с бОльшим выходом, не обработкой.
- **Спектр гитары узкий**: пик около 2 кГц, ниже 125 Гц и выше 8 кГц почти пусто - acoustic-симулятор NUX режет края. Подъёмы «воздуха» на 12 кГц бессмысленны.
- **Голос тёмный и бубнящий**: пик около 250 Гц, провал около 1 кГц, перекос до 14 дБ - близкая работа с динамическим микрофоном. Лечится вырезом низкой середины и подъёмом 2.5-4 кГц.
- **Маскирование в 1-2 кГц** - гитара занимает область разборчивости голоса. Работает встречная правка: вырез у гитары на 2 кГц, подъём у голоса на 2.5 кГц.

## Границы

Замеры ловят клиппинг, гул, перекос спектра, задавленную динамику и конфликт частот. «Звучит ли это хорошо» они не решают. Если замер расходится с тем, что слышит пользователь - прав пользователь.
